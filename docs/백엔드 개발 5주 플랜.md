## 1주차 — 환경 설정 + JPA 엔티티 완성

**목표:** Spring Boot가 정상 기동되고 DB 테이블이 생성되는 것 확인

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | 개발 환경 | Docker + Oracle DB 개념, `docker-compose.yml` 읽기 | `docker-compose up -d` 실행, `healthy` 확인 |
| 2일 | 엔티티 (기존) | JPA `@Entity`, `@MappedSuperclass`, `@GeneratedValue` 어노테이션 의미 파악 | 이미 작성된 엔티티 5개 코드 직접 읽으면서 이해 |
| 3일 | 엔티티 (신규) | enum, `@Enumerated`, `@SQLRestriction`, `@PrePersist` 이해 | `Participant`, `ParticipantType`, `Availability`, `AvailabilityStatus` 작성 |
| 4일 | Repository | Spring Data JPA `JpaRepository` 제네릭, 메서드 쿼리 규칙 이해 | Repository 5개 작성 |
| 5일 | 공통 / 예외 처리 | `@ControllerAdvice`, `@ExceptionHandler` 이해 | `ApiResponse`, `ErrorCode`, `CustomException`, `GlobalExceptionHandler` 작성 + `bootRun` 기동 확인 |

**완료 기준**
- [ ] `Started BackendApplication` 콘솔 출력 확인
- [ ] DBeaver에서 테이블 5개(`USERS`, `MEETINGS`, `CANDIDATE_SLOTS`, `PARTICIPANTS`, `AVAILABILITIES`) 생성 확인

## 2주차 — Spring Security + JWT + 카카오 OAuth

**목표:** 카카오 로그인 후 JWT 발급까지 Postman으로 성공

> 이 주차가 전체에서 가장 어렵고 중요합니다. 막히는 게 당연하니 시간 여유를 두세요.

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | Security 설정 | Spring Security 필터 체인 개념, Stateless 인증 방식 이해 | `build.gradle`에 Security + JWT 의존성 추가 |
| 2일 | JWT 발급 / 검증 | JWT 구조(Header.Payload.Signature), `io.jsonwebtoken` 라이브러리 이해 | `JwtProvider` 작성 |
| 3일 | JWT 인증 필터 | `OncePerRequestFilter`, `SecurityContextHolder` 동작 원리 이해 | `JwtAuthFilter` + `SecurityConfig` 작성 |
| 4일 | 카카오 OAuth | 카카오 OAuth 인가 코드 플로우 (코드 → 액세스 토큰 → 사용자 정보) | 카카오 개발자 콘솔 세팅 + `AuthService` 작성 |
| 5일 | 인증 API | — | `AuthController` + DTO 2개 작성 + Postman Phase 1 검증 |

**완료 기준**
- [ ] `POST /api/auth/kakao/callback` → `accessToken`, `refreshToken` 수신 성공
- [ ] `POST /api/auth/refresh` → 새 accessToken 발급 성공
- [ ] 잘못된 인가 코드로 요청 시 `401 KAKAO_AUTH_FAILED` 응답 확인

## 3주차 — 모임 생성/조회 + 참가자 등록

**목표:** 모임을 만들고, 초대 링크로 참가자가 등록되는 흐름 완성

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | 모임 생성 (DTO) | `@Valid`, `@NotBlank`, `@FutureOrPresent` 등 Bean Validation 이해 | `MeetingCreateRequest`, `MeetingResponse` DTO 작성 |
| 2일 | 모임 생성 (서비스) | `@Transactional` 전파 방식, `readOnly = true` 의미 이해 | `MeetingService` 작성 (create, findByInviteToken, findByResultToken) |
| 3일 | 모임 생성 / 조회 API | — | `MeetingController` 작성 + Phase 2·3 Postman 검증 |
| 4일 | 참가자 등록 (서비스) | 비회원 처리 설계 이해 (JWT 없이 `X-Guest-Token` 헤더로 식별하는 방식) | `ParticipantService` 작성 (회원/비회원 분기, 중복 이름 처리) |
| 5일 | 참가자 등록 API | — | `ParticipantController` 작성 + Phase 4 Postman 검증 |

**완료 기준**
- [ ] `POST /api/meetings` → 201, inviteToken/resultToken 포함 응답 확인
- [ ] `GET /api/meetings/invite/{token}` → 모임 정보 + 슬롯 목록 확인
- [ ] 회원/비회원 참가자 등록, 중복 방지(`409`), 비회원 재방문 복원 모두 통과

## 4주차 — 가용 시간 제출 + 결과 조회

**목표:** 각자 가능한 시간을 제출하고, 집계 결과를 볼 수 있는 상태

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | 가용 시간 제출 (DTO) | UPSERT 패턴 이해 (없으면 insert, 있으면 update) | `AvailabilitySubmitRequest` DTO 작성 |
| 2일 | 가용 시간 제출 (서비스) | 트랜잭션 내에서 반복 save 동작 이해 | `AvailabilityService` 작성 (upsert, submit) |
| 3일 | 가용 시간 제출 API | — | `AvailabilityController` 작성 + Phase 5 Postman 검증 |
| 4일 | 결과 조회 (서비스) | Java Stream `Comparator`, `switch expression` 이해 | `ResultService` 작성 (집계, 추천 정렬 3가지) |
| 5일 | 결과 조회 API | — | `MeetingController`에 results 엔드포인트 추가 + Phase 6 Postman 검증 |

**완료 기준**
- [ ] `PUT /api/meetings/{token}/availabilities` → UPSERT 동작 확인 (재요청 시 중복 생성 없음)
- [ ] `POST .../participants/me/submit` → submittedAt 반환 확인
- [ ] `GET .../results` → 추천순/날짜순/시간순 정렬 3가지 모두 확인

## 5주차 — 모임 상태 관리 + 내 목록 + 마무리

**목표:** 전체 API 완성 + 프론트 연동 가능한 상태

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | 모임 확정 / 만료 / 취소 | 소프트 딜리트(`deleted_at`) 개념, `@SQLRestriction` 동작 재확인 | Phase 7 이미 구현된 confirm/expire/cancel Postman 검증 |
| 2일 | 내 모임 목록 | Spring Data `Page`, `Pageable` 개념 이해 | `MyController` 작성 + Phase 8 Postman 검증 |
| 3일 | CORS / 프론트 연동 | CORS 개념 (브라우저의 Same-Origin Policy) | `SecurityConfig`에 CORS 설정 추가, 프론트와 연결 테스트 |
| 4일 | 통합 테스트 | — | 전체 플로우 통합 테스트 (로그인 → 모임 생성 → 참가 → 제출 → 결과 조회 → 확정) |
| 5일 | 버퍼 | — | 막혔던 부분 재정리, 트러블슈팅 문서 참고 |

**완료 기준**
- [ ] `POST /api/meetings/{id}/confirm` → CONFIRMED 상태 전환 확인
- [ ] 이미 확정된 모임 재확정 시 `409 MEETING_ALREADY_CONFIRMED` 확인
- [ ] `GET /api/my/meetings?status=OPEN&page=0&size=5` → 페이징 응답 확인
- [ ] 전체 16개 API Postman 통과

## 주의할 점

- **2주차가 핵심입니다.** Spring Security 개념 없이 코드만 복붙하면 나중에 에러 났을 때 손도 못 댑니다. 하루 정도는 코드 없이 개념만 읽는 날로 써도 됩니다.
- **막히면 트러블슈팅 섹션 먼저 확인하세요.** [백엔드 설명.md](./백엔드%20설명.md) 맨 아래에 JWT 401 오류, KOE320 오류 등 흔한 문제가 정리되어 있습니다.
- **Postman 검증을 절대 건너뛰지 마세요.** 다음 Phase로 넘어갔다가 앞 단계 버그가 숨어있으면 나중에 찾기 훨씬 힘들어집니다.
- **막히는 날이 있어도 괜찮습니다.** 5주차 마지막 이틀은 버퍼입니다. 앞 주차에서 밀린 내용을 이 시간에 채우면 됩니다.
