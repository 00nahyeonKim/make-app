## 1주차 — 환경 설정 + JPA 엔티티 완성

**목표:** Spring Boot가 정상 기동되고 DB 테이블이 생성되는 것 확인

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | Docker / Oracle DB 환경 구성 | Docker + Oracle DB 개념, `docker-compose.yml` 읽기 | `docker-compose up -d` 실행, `healthy` 확인 |
| 2일 | `User` · `Meeting` · `CandidateSlot` 엔티티 | JPA `@Entity`, `@MappedSuperclass`, `@GeneratedValue` 어노테이션 의미 파악 | 이미 작성된 엔티티 5개 코드 직접 읽으면서 이해 |
| 3일 | `Participant` · `Availability` 엔티티 | enum, `@Enumerated`, `@SQLRestriction`, `@PrePersist` 이해 | `Participant`, `ParticipantType`, `Availability`, `AvailabilityStatus` 작성 |
| 4일 | JPA Repository 5종 | Spring Data JPA `JpaRepository` 제네릭, 메서드 쿼리 규칙 이해 | Repository 5개 작성 |
| 5일 | 공통 응답 · 예외 처리 | `@ControllerAdvice`, `@ExceptionHandler` 이해 | `ApiResponse`, `ErrorCode`, `CustomException`, `GlobalExceptionHandler` 작성 + `bootRun` 기동 확인 |

**완료 기준**
- [ ] `Started BackendApplication` 콘솔 출력 확인
- [ ] DBeaver에서 테이블 5개(`USERS`, `MEETINGS`, `CANDIDATE_SLOTS`, `PARTICIPANTS`, `AVAILABILITIES`) 생성 확인

## 2주차 — Spring Security + JWT + 카카오 OAuth

**목표:** 카카오 로그인 후 JWT 발급까지 Postman으로 성공

> 이 주차가 전체에서 가장 어렵고 중요합니다. 막히는 게 당연하니 시간 여유를 두세요.

| 일차 | 기능 | 학습 | 작업 |
|------|------|------|------|
| 1일 | Spring Security 기반 설정 | Spring Security 필터 체인 개념, Stateless 인증 방식, BCrypt 이해 | `build.gradle`에 Security + JWT 의존성 추가, `SecurityConfig`에 `BCryptPasswordEncoder` Bean 등록 |
| 2일 | JWT 토큰 발급 · 검증 (`JwtProvider`) | JWT 구조(Header.Payload.Signature), Claim 이해 | `JwtProvider` 작성 (소셜용 + 게스트용 `createGuestToken`) |
| 3일 | JWT 인증 필터 · Cookie 기반 인증 | `OncePerRequestFilter`, HttpOnly Cookie 개념 | `JwtAuthFilter`(Cookie 읽기 + ROLE_GUEST 분기) + `SecurityConfig`(CORS `allowCredentials`) 작성 |
| 4일 | 카카오 OAuth + 게스트 인증 (`AuthService`) | 카카오 인가 코드 플로우, BCrypt `matches` 동작 이해 | 카카오 개발자 콘솔 세팅 + `AuthService` 작성 (`kakaoLogin` + `guestRegister` + `guestLogin`) |
| 5일 | 인증 API — 소셜 · 게스트 · 로그아웃 | HttpOnly Cookie `ResponseCookie` 생성 방법 | `AuthController` + DTO 4개(`KakaoCallbackRequest`, `TokenRefreshRequest`, `GuestRegisterRequest`, `GuestLoginRequest`) + Postman Phase 1 검증 |

**완료 기준**
- [ ] `POST /api/auth/kakao/callback` → 응답 헤더에 `Set-Cookie: access_token=...; HttpOnly` 확인
- [ ] `POST /api/auth/refresh` → 새 accessToken 발급 + Cookie 갱신 성공
- [ ] 잘못된 인가 코드로 요청 시 `401 KAKAO_AUTH_FAILED` 응답 확인
- [ ] `POST /api/auth/guest/register` → 201, Cookie 발급, 참가자 정보 반환 확인
- [ ] `POST /api/auth/guest/login` → 200, 기존 참가자 정보 반환 확인
- [ ] PIN 5회 실패 후 `429 PIN_LOCKED` 응답 확인

| 4일 | 참가자 등록 서비스 — 회원만 처리 (`ParticipantService`) | Cookie JWT 기반 `Authentication` 분기 이해 (`ROLE_GUEST` 권한 체크) | `ParticipantService` 작성 (MEMBER 분기, 중복 이름 처리, `findMe` 게스트/회원 분기) |

## 주의할 점

- **2주차가 핵심입니다.** Spring Security 개념 없이 코드만 복붙하면 나중에 에러 났을 때 손도 못 댑니다. 하루 정도는 코드 없이 개념만 읽는 날로 써도 됩니다.
- **비회원 인증은 X-Guest-Token 헤더 방식을 사용하지 않습니다.** 닉네임 + PIN 해시 + HttpOnly Cookie 방식으로 설계되어 있으니 [백엔드 설명.md](./백엔드%20설명.md)의 Phase 1 게스트 등록/로그인 섹션을 먼저 읽으세요.
- **막히면 트러블슈팅 섹션 먼저 확인하세요.** [백엔드 설명.md](./백엔드%20설명.md) 맨 아래에 JWT 401 오류, KOE320 오류, CORS 쿠키 오류 등 흔한 문제가 정리되어 있습니다.
- **Postman 검증을 절대 건너뛰지 마세요.** Postman에서 쿠키 전송 시 Settings → Cookies에서 `localhost` 도메인 쿠키가 활성화되어 있어야 합니다.
- **막히는 날이 있어도 괜찮습니다.** 5주차 마지막 이틀은 버퍼입니다. 앞 주차에서 밀린 내용을 이 시간에 채우면 됩니다.
