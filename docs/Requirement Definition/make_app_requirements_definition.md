## 1. 개요

### 1.1 서비스 한 줄 요약

초대 URL을 통해 지인들이 가능한 시간을 선택하고, 리더가 최적의 약속 시간을 확정하는 일정 조율 서비스.

### 1.2 문서 목적

이 문서는 Make-App 서비스 구현에 필요한 기능 요구사항과 비기능 요구사항을 정의한다. 리더, 팔로워, 비회원 팔로워의 사용 흐름을 기준으로 화면, 인증, 일정 생성, 참여, 결과 조회, 공유, 식별 및 권한 요구사항을 정리한다.

### 1.3 주요 사용자 역할

| 역할 | 설명 | 주요 식별 방식 |
|---|---|---|
| 공통 사용자 | 메인 화면, 서비스 소개, 일정 만들기 진입, 마이페이지 흐름을 이용하는 사용자 | 로그인 상태 또는 공개 접근 |
| 리더 | 모임을 생성하고 초대 URL을 공유하며 최종 일정을 관리하는 사용자 | 소셜로그인 `userId` |
| 팔로워 | 공유받은 URL로 접속하여 본인의 가능 시간을 등록하는 참여자 | 소셜로그인 `userId` 또는 비회원 `guestToken` |

## 6. 핵심 비즈니스 규칙

### 6.1 인증 및 식별

- 리더가 일정을 만들기 위해서는 반드시 소셜로그인을 해야 한다.
- 로그인한 리더와 소셜로그인 팔로워는 서비스 내부 `userId`로 식별한다.
- 비회원 팔로워는 이름 또는 닉네임을 입력하고, 서버에서 발급한 `guestToken`으로 식별한다.
- 같은 브라우저에서 재접속한 비회원은 저장된 `guestToken`을 통해 기존 입력 정보를 불러올 수 있어야 한다.

### 6.2 모임 생성 및 초대

- 모임명, 후보 날짜, 후보 시간 등 필수값이 없으면 모임 생성이 제한되어야 한다.
- 리더가 선택한 후보 날짜와 시간은 DB에 저장되어야 한다.
- 일정 생성 완료 시 예측하기 어려운 `inviteToken` 또는 UUID가 포함된 고유 초대 URL을 생성해야 한다.
- 리더는 생성된 URL을 버튼 클릭으로 복사할 수 있어야 한다.

### 6.3 참여와 응답

- 팔로워는 리더가 설정한 후보 날짜와 시간 중 자신의 가능 시간을 선택할 수 있어야 한다.
- 팔로워는 자신의 선택을 수정할 수 있어야 하며, 자신의 일정만 수정할 수 있어야 한다.
- 동시에 여러 사용자가 입력해도 데이터가 정상 저장되어야 한다.
- 팔로워가 일정을 등록하면 완료 상태가 표시되어야 한다.

### 6.4 결과와 공유

- 결과 화면은 날짜와 시간대별 가능한 인원 수를 표시해야 한다.
- 가능한 인원이 많은 시간 순서대로 추천 결과를 정렬할 수 있어야 한다.
- 추천 결과에는 `5명 중 4명 가능`과 같은 기준이 표시되어야 한다.
- 사용자는 일정 조율 결과를 공유할 수 있어야 하며, 결과 공유용 URL이 생성되어야 한다.

### 6.5 권한 검증

- 각 모임은 생성한 리더의 `userId`를 `ownerId`로 저장해야 한다.
- 모임 수정, 삭제, 결과 확정 등 리더 기능은 `ownerId`와 로그인 `userId`가 일치할 때만 가능해야 한다.
- 타인의 일정 선택 데이터를 임의로 수정할 수 없어야 한다.
